## 2026-05-11 — Phase 0 Slice 1: Regenerate migration

Procedure:

The new migration intentionally still creates the legacy `team_a`/`team_b`/`ticker_a`/`ticker_b`/`closes_at` (on `markets`), `reserve_a`/`reserve_b`, and `shares_a`/`shares_b` columns. Slice 1 is additive — the actual drops happen in Phase 1.

## 2026-05-11 — Phase 0 Slice 1: Rewrite `translateKalshiEvent` happy path

Reshaped the translator's output to the new multi-outcome model: a single Kalshi Event now produces one `TranslatedEventRow` plus N `TranslatedMarket` rows (each a YES-side wampum Market) instead of one collapsed A/B Market.

Key changes to `src/lib/kalshi/translator.ts`:
- New return shape: `{kind: 'ok', value: {event, markets: TranslatedMarket[]}}`.
- `TranslatedEventRow = Omit<events.$inferInsert, "status" | "createdAt">`.
- `TranslatedMarketRow = Omit<markets.$inferInsert, "status" | "createdAt" | "eventId">`. `eventId` is set during DB insertion by the consumer.
- Per-child `initialProbabilityYes` (renamed from the pair-averaged `initialProbabilityA`) sourced from each child's own YES-side bid/ask midpoint.
- Dropped the `non_binary` reject — translator now iterates `event.markets` instead of destructuring `[a, b]`.
- Dropped the `pair_inconsistent` reject — under the new model each child is an independent YES/NO contract with no cross-sibling check.
- `InsufficientConfidenceReason` is now `{ ticker, reason: 'spread_too_wide' }` per failing child, aggregated across siblings (still all-or-nothing at the Event level).
- `event.id = kalshi-${event_ticker}`; `market.id = kalshi-${market.ticker}` per child.
- Legacy `teamA`/`teamB`/`tickerA`/`tickerB` columns on `markets` are still NOT NULL during Slice 1's additive transition, so each translated child Market populates them with placeholder values (`teamA = yes_sub_title`, `teamB = ""`). They'll be dropped in Phase 1.
- `translateKalshiResolution` left intact (it's replaced by `decideEventCommit` in Phase 3).

### Consumer adaptation
`createMarket` in `src/data/markets.ts` is rewritten to `createEvent` in the next plan task, but it has to keep compiling until then:
- Inlined a `LegacyCreateMarketInput` type so `data/markets.ts` no longer imports `TranslatedMarket` from the translator. The function body still does the pre-multi-outcome single-row write.
- In `src/lib/kalshi/ingest.ts`, added a thin Slice 1 shim: take the new translator output, pick the first two child markets, and collapse them back into the legacy A/B input for `createMarket`. The shim is explicitly marked transitional and will be removed when `createEvent` lands.
- Removed `non_binary` from `SkipReasonKind` and the empty-counters initializer.

Translator tests rewritten (`src/lib/kalshi/translator.test.ts`):
- Happy path now asserts one `event` row + N child `markets` rows, including per-child `initialProbabilityYes`.
- Removed `non_binary` and `pair_inconsistent` cases (fixtures stay around for now — deletion is in Phase 6).
- `insufficient_confidence` test now matches the new per-child reason shape `{ ticker, reason: 'spread_too_wide' }`.

## 2026-05-11 — Phase 0 Slice 1: Add `createEvent` in `data/events.ts`

Created `src/data/events.ts` with the new `createEvent` function that consumes the translator's `TranslatedEvent` shape (`{event, markets[]}`) and persists one `events` row + N `markets` rows + N `ammPools` rows in a single DB transaction. Per-Market `initializePool` seeding debits the treasury once per child Market and emits one `CreateMarket` transaction row per child.

`ingest.ts` now calls `createEvent(result.value)` directly, replacing the Slice 1 A/B-collapsing shim that wrapped the legacy `createMarket`. The ingest driver is now N-Market-capable for the happy path (Slice 2 still needs the rejection variants `too_many_markets` and `inconsistent_close_times`).

### Mapping legacy AMM reserves to YES-first reserves
`initializePool` (still in legacy A/B form during Slice 1) returns `sharesA`/`sharesB`. Under the YES-first model, `sharesA → reserveYes` and `sharesB → reserveNo`. The mapping holds because the legacy `calculatePrices` defines `priceA = sharesB / total` — so feeding `initialProbabilityYes` directly as the `initialProbabilityA` argument makes `priceA = priceYes` and therefore the "A" reserve is the YES reserve. The `ammPools` insert populates both legacy (`reserveA/B`) and new (`reserveYes/No`) columns to keep downstream consumers compiling until Phase 1 drops the legacy pair.

### Legacy `createMarket` retention
`createMarket` in `src/data/markets.ts` is kept (not deleted) because `tests/integration/bet-and-resolve.test.ts` still imports and calls it. The integration test is slated for rewrite in Phase 6; removing `createMarket` now would break the typecheck on a file outside the Slice 1 scope.
