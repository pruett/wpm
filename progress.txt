## 2026-05-11 — Phase 0 Slice 1: Adapt settlement + inline commitEvent

Folded per-child resolve/cancel work into a single transactional `commitEvent` driven by a new event-level settlement primitive. `commitEvent` no longer dispatches to `resolveMarket`/`cancelMarket` — it loads every child's pool + position rows in one pass, runs the pure decision function `computeEventSettlement`, and applies all balance credits, treasury moves, pool drains, market status flips, and ledger rows inside one `db.transaction`.

### New `computeEventSettlement` (`lib/settlement.ts`)
Additive — sits alongside the legacy per-child `computeSettlement` (still used by `resolveMarket`/`cancelMarket` for the integration test). Takes `{perChild: EventSettlementChildInput[]}` where each child carries its `outcome` (`resolved_yes`/`resolved_no`/`cancelled_*`), its `wpmReserve`, and a flat YES-only `positions[]` (`{userId, shares, costBasis}`). Returns per-child output bundles with `payouts`, `treasuryDelta`, `backstopAmount`, `finalStatus`, and `resolvedAs`.

Per-child semantics match PRD §Settlement:
- `resolved_yes`: holders with `shares > 0n` → `win` row of `amount = shares` (since YES shares pay 1 WPM each).
- `resolved_no`: holders with `shares > 0n` → `loss` row of `amount = 0n` (still emitted per PRD).
- `cancelled_*`: refund `costBasis` (or `zero` row if `costBasis = 0n`).

The function is pure — no DB I/O, no clock — so it'll slot into the Phase 3 settlement tests without further reshaping.

### Inlined `commitEvent` (`src/data/events.ts`)
- Opens one `db.transaction` for the whole event.
- Guards: `event_not_found` / `event_not_open` short-circuit.
- Loads `markets`/`amm_pools`/`positions` for the child set in parallel via `Promise.all`.
- Pre-flight pass classifies each child: already-resolved children get `{alreadyResolved: true}` without re-running settlement (idempotency under retry); already-cancelled likewise; missing market/pool emits an error result; remaining children feed into `settleablePlan`.
- Single call to `computeEventSettlement`.
- `applyChildSettlement` writes per-child: `balances` credits (only for `amount > 0`), `SettlePayout` rows (always, including loss/zero), `treasury` backstop or sweep with a `TreasuryBackstop` row when backstop fires, zeros `ammPools.wpmReserve`, flips `markets.status` to `resolved`/`cancelled`, and writes the `ResolveMarket`/`CancelMarket` transaction row.
- Final write flips `events.status='terminal'`.

### Legacy retention
- `resolveMarket`/`cancelMarket` in `data/markets.ts` are untouched — the integration test still calls them. `computeSettlement` (legacy single-child) is also untouched. Both go away in Phase 6 when the integration test is rewritten.
- `markets.resolvedOutcome` (A/B) is dual-written alongside `markets.resolvedAs` (yes/no) during the additive transition — A === yes under the YES-first mapping. Phase 1 drops the legacy column.

## 2026-05-11 — Phase 0 Slice 2: Multi-outcome ingest smoke test

Added an integration test that exercises the multi-outcome ingest path end-to-end against a real Postgres database, using the 5-Market `multi-outcome-healthy.json` fixture as the driver.

Test flow:
1. Seed treasury.
2. Translate the fixture through `translateKalshiEvent` and assert the `ok` translation has 5 child Markets.
3. Call `createEvent(translation.value)` and verify it returns `{created: true}`.
4. Assert one `events` row exists with `sport='nba'`, `status='open'`.

6. For each child market, load its `amm_pools` row and assert that
   `priceYes = reserveNo / (reserveYes + reserveNo)` matches the translator's
   per-child midpoint within `toBeCloseTo(_, 3)` rounding tolerance.

Added as a second `describe` block in `tests/integration/event-flow.test.ts` to share the existing mocks, db client setup, and TRUNCATE helpers with the Slice 1 smoke test.

### Why this satisfies Slice 2

The other three Slice 2 line items (translator N-Market path, all-or-nothing rejection, single-tx ingest persistence) were already implemented during Slice 1 — see prior progress entries for the translator rewrite and `createEvent`. This smoke test is the only outstanding deliverable that exercises those changes on N>2 children against a real DB, which is what the plan called for.

### Verification probability assertion

`initializePool` derives reserves from `initialProbabilityYes` as:
- `probBps = round(probYes * 10000)`, `total = 2 * seed`
- `sharesA = total * (10000 - probBps) / 10000` → `reserveYes`
- `sharesB = total - sharesA` → `reserveNo`

So `priceYes = reserveNo / (reserveYes + reserveNo) ≈ probYes`. The 3-decimal tolerance absorbs the bps rounding (each bps is 0.0001).

The pool read uses `pool.reserveYes ?? pool.reserveA` (and equivalent for No) to be resilient to the Slice 1 additive transition where both legacy and new reserve columns coexist — in `createEvent` the new columns are populated, but the fallback keeps the test robust if that ever flips.

## 2026-05-11 — Phase 2: Add `too_many_markets` translator variant

Added a hard cap on child Markets per Event in the translator. Events with >30 children are now rejected wholesale via a new `too_many_markets` discriminated-union variant, before any other validation runs.

Changes in `src/lib/kalshi/translator.ts`:
- Added `MAX_MARKETS_PER_EVENT = 30` constant, sourced from PRD §Further Notes (also documented as an assumption at the top of `PLAN.md`).
- New `TranslationResult` variant: `{ kind: 'too_many_markets', eventTicker, count }`. Carries both the event ticker (for logging consistency with sibling variants) and the actual market count (so operators can see how badly the cap was breached).
- Check runs first in `translateKalshiEvent`, before close-time parsing and per-Market quote/spread checks. Failing fast keeps oversized payloads out of the heavier downstream validation.

Changes in `src/lib/kalshi/ingest.ts`:
- `SkipReasonKind` automatically picks up the new variant via its `Exclude<TranslationResult["kind"], "ok">` definition, but `emptySkipCounters()` had to be updated to initialise the new `too_many_markets: 0` field — `Record<SkipReasonKind, number>` enforces exhaustiveness.

### Test fixture choice
Instead of authoring a 31-market JSON fixture, the new test case constructs the oversized event in-memory by cloning a child from `binary-healthy.json` 31 times. Two reasons:
1. The JSON would be ~31× redundant — every child carries the same shape, only the ticker varies.
2. A real 31-Market Kalshi Event doesn't exist for any current series; an in-memory construction is more honest about the test's purpose (cap enforcement) than a fabricated fixture.

The clone uses `Array.from({ length: 31 }, (_, i) => ({ ...child, ticker: `...-${i}` }))` so each child has a distinct ticker (translator does not currently dedupe, but giving each child a unique ticker matches the production shape).

## 2026-05-11 — Phase 3: Deadline degradation in `decideEventCommit`

Implemented the 48h Settlement Deadline degradation branch in
`decideEventCommit`. When `now >= closesAt + 48h` and any child Market is
non-terminal on Kalshi's side, that child is now committed as
`cancelled_no_settlement` (cost-basis refund) so the Event commits rather than
blocking indefinitely. Cleanly-settled siblings still resolve on their actual
`result` in the same commit plan.

### Implementation notes
- Added `SETTLEMENT_DEADLINE_MS = 48 * 60 * 60 * 1000` module-level constant
  (PRD §Further Notes calls it out as baked-in for v1).
- `deadlineReached = now >= wampumEvent.closesAt + SETTLEMENT_DEADLINE_MS` is
  computed once at the top of the function. The per-child loop branches on it:
  - non-terminal child + deadlineReached → push `cancelled_no_settlement`.
  - non-terminal child + before deadline → return `{kind: 'wait'}` (preserves
    pre-deadline behaviour).
  - terminal child + unrecognised result + deadlineReached → also degrade to
    `cancelled_no_settlement` so a malformed terminal payload past the
    deadline doesn't stall the Event. This is a small policy extension beyond
    the strict "non-terminal" reading of the PRD, but matches the deadline's
    intent: bound the worst-case duration of a stuck position.
  - terminal child + unrecognised result + before deadline → still returns
    `wait` so operators have a chance to inspect the malformed payload.
